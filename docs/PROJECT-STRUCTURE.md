# Project Structure Guide

## Reading order

When entering the project for the first time, read these files in this order:

1. `README.md`
2. `CLAUDE.md`
3. `data/catalog.ts`
4. `data/media.ts`
5. `lib/date.ts`
6. `i18n/config.ts`
7. `i18n/request.ts`
8. `components/Shell.tsx`
9. `components/Navbar.tsx`
10. `app/globals.css`
11. The route being modified under `app/`

This order moves from project intent to data, infrastructure, shared shell, visual system and finally page-specific implementation.

## Data first

Domain data belongs in `data/`.

Components should consume approved data rather than inventing content. If a component needs a new field, the contract must be reviewed before adding it.

## Media first

All production media references should be easy to locate from `data/media.ts`.

Do not place an isolated production URL directly inside a page component when the media belongs to the approved catalog.

## Localization first

Visible text belongs in `messages/`.

Use the feature file that owns the content. Shared UI text belongs in `common.json`.

## Presentation

Reusable presentation belongs in `components/`.

Route-specific composition belongs in `app/`.

Global visual behavior belongs in `app/globals.css`.

## CSS organization

`app/globals.css` is divided conceptually into:

1. Theme and typography tokens
2. Global/reset rules
3. Navigation
4. Shared layout
5. Home/hero
6. Progress/countdown
7. Cards and content blocks
8. Detail pages
9. Media/carousels/trailers
10. Responsive rules
11. Loading state
12. Accessibility/reduced-motion rules
13. Small layout helpers
14. Relationship list

Do not compress a rule merely to reduce file length.

## Generated files

Never treat `.next/` as source. It is generated by Next.js.

Do not add `.next/dev/`, `.next/cache/` or generated build output to the project archive.

## Project instructions

`CLAUDE.md` is the technical operating guide for AI-assisted changes. It does not replace the Master Document. When modifying the project, read `README.md` and `CLAUDE.md` before touching implementation.

## Branding

The navbar uses one unified `GTA VI + ⚡` visual mark. The same approved local PNG mark is used by the navbar and `app/icon.png` so the site identity does not get reconstructed from separate text, image and icon pieces. Keep the mark centralized at `public/brand/gta-vi-lightning.png` and do not recreate it inside individual route components.
